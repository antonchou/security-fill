ACME CLOUD SECURITY POLICY
Version 2.1 · Effective 2026-01-01
Classification: Internal

1. PURPOSE
This policy defines information security requirements for Acme Cloud Software, Inc. ("Acme")
systems, personnel, and third-party processors.

2. ACCESS CONTROL
2.1 All production systems require multi-factor authentication (MFA). Password-only access is prohibited.
2.2 Access is granted on a least-privilege basis. Role-based access control (RBAC) is enforced via SSO (Okta).
2.3 Privileged (admin) access is time-bound, logged, and reviewed quarterly.
2.4 User access is revoked within 24 hours of employment termination.
2.5 Shared accounts are not used for production administrative access.

3. ENCRYPTION
3.1 Data in transit is protected with TLS 1.2 or higher. TLS 1.0/1.1 are disabled.
3.2 Data at rest in production databases and object storage is encrypted with AES-256 (provider-managed or CMK).
3.3 Secrets (API keys, certificates) are stored in a secrets manager (HashiCorp Vault / cloud secret manager).
    Secrets are never committed to source control.

4. LOGGING AND MONITORING
4.1 Authentication events, admin actions, and security-relevant API calls are logged centrally.
4.2 Logs are retained for a minimum of 12 months.
4.3 Security alerts are triaged by the on-call engineer within defined SLAs.
4.4 We do not provide customers with direct SIEM access; summary security reports are available on request.

5. VULNERABILITY MANAGEMENT
5.1 Production dependencies and container images are scanned weekly.
5.2 Critical vulnerabilities are remediated within 7 days; high within 30 days.
5.3 External penetration testing is performed at least annually by an independent firm.
5.4 A public vulnerability disclosure email is available: security@acme.example.

6. BACKUP AND DISASTER RECOVERY
6.1 Production databases are backed up daily with point-in-time recovery.
6.2 Backups are encrypted and stored in a separate availability region.
6.3 Disaster recovery objectives: RPO 24 hours, RTO 8 hours for tier-1 services.
6.4 DR restore tests are performed at least annually.

7. INCIDENT RESPONSE
7.1 Acme maintains a documented incident response plan covering detection, containment, eradication, and recovery.
7.2 Customers are notified of confirmed breaches affecting their data without undue delay, and within 72 hours where legally required.
7.3 Post-incident reviews are documented with corrective actions.

8. EMPLOYEE SECURITY
8.1 Background checks are conducted for employees with production access where legally permitted.
8.2 Security awareness training is completed at hire and annually thereafter.
8.3 Acceptable use and confidentiality agreements are signed by all staff.

9. NETWORK SECURITY
9.1 Production networks are segmented from corporate workstations.
9.2 Security groups / firewall rules default to deny. Public exposure is minimized and reviewed.
9.3 Web application firewall (WAF) protects public HTTP endpoints.
9.4 We do not permit unrestricted inbound SSH from the public internet to production hosts.

10. DATA RETENTION AND DELETION
10.1 Customer data is retained for the subscription term plus 30 days unless otherwise agreed.
10.2 Upon verified deletion requests, data is deleted from production within 30 days and from backups within the backup rotation cycle.
10.3 Data processing agreements (DPA) are available for enterprise customers.

11. COMPLIANCE AND AUDITS
11.1 Acme maintains SOC 2 Type II for Security (report available under NDA).
11.2 We map controls to SOC 2 Trust Services Criteria; ISO 27001 certification is on the roadmap for 2027.
11.3 Subprocessors are listed at trust.acme.example and updated when material changes occur.

12. SECURE DEVELOPMENT
12.1 Code changes require peer review via pull requests before merge to main.
12.2 CI/CD pipelines run SAST, dependency scanning, and unit tests before production deploy.
12.3 Production deploys are automated; manual hotfixes require dual approval.
12.4 AI-assisted coding tools are allowed; secrets scanners run on every PR.

13. BUSINESS CONTINUITY
13.1 Critical vendors and cloud regions are reviewed annually for concentration risk.
13.2 Status page: status.acme.example communicates incidents and maintenance windows.
